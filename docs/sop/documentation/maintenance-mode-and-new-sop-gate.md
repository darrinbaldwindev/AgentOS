# SOP Library Maintenance Mode and New-Document Gate

**Document ID:** SOP-DOC-002
**Status:** DRAFT

## Objective
Stop documentation growth from becoming an end in itself. After the remaining high-value closure set is complete, the SOP library enters maintenance mode.

## Create a new SOP only when
- a genuinely new capability/action class introduces a new operational/governance requirement;
- a jurisdiction/operator/activity creates a materially distinct legal/compliance workflow;
- existing SOPs cannot express a safety/recovery/evidence boundary without becoming ambiguous; or
- repeated incidents/tests demonstrate a missing control domain.

## Prefer updating/consolidating when
The new material is another example, provider, UI surface, product variant, project instance or test case of an existing rule.

## Maintenance priorities
1. map P0 SOP rules to enforcement/tests/evidence;
2. remove contradictions and stale claims;
3. archive/supersede obsolete docs;
4. revalidate after implementation/legal/product changes;
5. keep user docs derived from current evidence;
6. measure unmapped/unverified requirements.

## Completion signal
Documentation maturity is not document count. A stronger signal is the percentage of material P0 requirements that are mapped to canonical enforcement, exact-head tests, receipts and independent verification.
